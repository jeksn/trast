# Trast

macOS menu-bar utility that applies user-defined window sizes/positions to the focused window (Raycast "Create Command" style), plus a Spotlight-like launcher with app launching, clipboard history, and snippet expansion. Native Swift 6 + SwiftUI, built with Swift Package Manager only — no Xcode project, works with Command Line Tools.

## Commands

```bash
swift build                  # debug build (app + tests)
swift run TrastTests    # run the test harness (exits non-zero on failure)
Scripts/package_app.sh       # release build + Trast.app bundle (version from latest git tag)
Scripts/dev.sh               # debug build + bundle + relaunch app
Scripts/update.sh            # release build + install to /Applications + relaunch
Scripts/make_dmg.sh          # release build + drag-to-Applications DMG in dist/
Scripts/install.sh [--force] # copy Trast.app to /Applications
```

There is no `swift test` workflow: this machine has Command Line Tools only (no full Xcode). CLT ships neither XCTest nor a working Swift Testing runtime (test bundles build but the runner discovers zero tests), so tests live in the `TrastTests` executable target and run via `swift run TrastTests`.

## Layout

- `Sources/TrastCore/` — dependency-free logic: `WindowDimension`, `Anchor` (two-axis struct with per-axis `keep` for move-style commands; decodes legacy flat strings like `"topLeft"`), `WindowCommand` (+ `seeds`, + `migratingLegacyCommands`), `LayoutEngine` (pure frame math + `frameForNextDisplay` for multi-display moves), `FuzzyMatch`, `TrastURL` parsing, `Snippet` (model: id, name, keyword, content, enabled; custom Codable with defaults for missing fields), `AppSettings`. All public API — consumed by both the app and tests.
- `Sources/Trast/` — app target: AX layer (`Accessibility`, `WindowManipulator`), `CommandApplier` (+ `RestoreStore`; intercepts the `nextDisplay` action before the normal LayoutEngine path to cycle `NSScreen.screens`), `CommandStore` (versioned JSON at `~/Library/Application Support/Trast/commands.json`; v2 = `{version, commands}`, legacy bare arrays migrate via `WindowCommand.migratingLegacyCommands`, which preserves IDs of name-matched commands so hotkeys survive), `AppShortcutStore` (versioned JSON at `~/Library/Application Support/Trast/appShortcuts.json`; `AppShortcut.Kind` = `app`, `url`, or `folder`), `ConfigPorter` (export/import combined JSON of both stores), `HotkeyManager`, menu bar + settings UI, `LauncherController`/`LauncherView`/`LauncherViewModel` (Spotlight-style launcher; borderless non-activating `NSPanel`; items grouped into Commands / Actions / Shortcuts / Applications / Trast sections; `LauncherAction` enum for app-level actions like Settings, Clipboard History, Check for Updates, Quit), `HUD` feedback, `URLDispatcher`, `ClipboardMonitor`/`ClipboardStore` (clipboard history; the launcher's Clipboard tab is the only UI for it), `SnippetStore`/`SnippetExpander` (snippet expansion via CGEvent tap), `HyperkeyEngine` (Caps Lock → ⌃⌥⇧⌘ hyper key). The `Launcher/` directory also contains `UsageTracker` (persists recency ordering in UserDefaults key `launcherUsageLog`).
- Commands carry `isDefault` (seeds; sidebar "Defaults" section, restorable via `restoreDefaults()`) and `showInMenuBar` (menu bar only lists pinned commands; toggle in the editor, indicator in the sidebar). New custom commands are pinned by default.
- **CI**: `.github/workflows/release.yml` builds/tests/DMGs on `v*` tag push and attaches the DMG to a GitHub Release. CI imports the signing certificate from repo secrets (`MACOS_SIGNING_P12` = base64 p12, `MACOS_SIGNING_PASSWORD` = export password) and signs with the stable identity — without the secrets it falls back to ad-hoc, which resets the Accessibility grant on update.
- **SPM resource bundles in packaged apps**: dependency packages with resources (KeyboardShortcuts) get a `Bundle.module` accessor that only checks the .app ROOT (codesign rejects placing bundles there) and an absolute path baked at build time. `package_app.sh` copies the bundles to `Contents/Resources/` and patches the baked path in the binary to `/Applications/Trast.app/Contents/Resources/<bundle>`, padding with path-safe slashes to preserve the baked string length (Swift literals are pointer+count, so the replacement must be same-length). Without the patch, packaged apps crash on any hotkey Recorder (Settings > General).
- **Updates**: `UpdateChecker` (app target) queries `https://api.github.com/repos/jeksn/trast/releases/latest` — **update the `repo` constant when the GitHub repo is created/renamed**. Compares via `VersionCompare` (Core), offers download-and-install (DMG asset → hdiutil → copy to /Applications → relaunch) or opening the release page. Bundle version comes from the latest git tag (`package_app.sh`), so tag releases `vX.Y.Z`.
- `Tests/TrastTests/` — custom harness (`TestRunner` + suite files + `main.swift`).

## Notes / gotchas

- **KeyboardShortcuts is pinned to exactly 1.10.0.** Newer 3.x uses SwiftUI `@Entry`/`#Preview` macros whose plugin dylibs (`SwiftUIMacros`, `PreviewsMacros`) do not ship with CLT — builds fail. Also, this environment's GitHub mirror only exposes tags up to v1.10.0.
- `onKeyUp` handlers APPEND (never replace): each command registers exactly once per UUID (`HotkeyManager.registeredCommandIDs`); handlers resolve the command dynamically from the store at fire time, so stale registrations are harmless no-ops. Deleting a command clears its shortcut via `KeyboardShortcuts.setShortcut(nil, for:)`.
- Offset semantics match Raycast: positive X offset moves right, **positive Y offset moves DOWN** (screen convention; the engine subtracts in Cocoa's bottom-left coordinates). Percent sizes/anchors/offsets are relative to `visibleFrame` inset by the global edge gap.
- `AppDelegate` registers the `trast://` URL scheme via `NSAppleEventManager` kAEGetURL. The event class/ID and direct-object keyword are hard-coded FourCharCode literals (`0x4755524C` = 'GURL', `0x2D2D2D2D` = '----') to avoid Carbon import issues with CLT.
- `WindowManipulator` uses the private `_AXUIElementGetWindow` (dlsym'd from ApplicationServices) to key restore geometry by CGWindowID; falls back to `pid-title` keys. Same approach as Rectangle/Loop.
- AX coordinates are top-left origin, NSScreen bottom-left; conversion helpers live in `WindowManipulator` (primary screen height based).
- Settings is a custom `Window` scene (id `settings`, title "Trast"), not the SwiftUI `Settings` scene — the `showSettingsWindow:` selector is unreliable in menu-bar apps on newer macOS. `MenuContent.openSettingsWindow()` activates the app, calls `openWindow(id:)`, then re-activates and orders the window front. The Launcher also opens Settings via a `NotificationCenter` post (`.openSettings`) observed by `MenuContent`.
- Settings uses a `NavigationSplitView` with a left sidebar (General, Window, Commands, Shortcuts, Snippets, Clipboard). Commands, Shortcuts, and Snippets use `HSplitView` for their sub-sidebar + detail; General, Window, and Clipboard use a grouped `Form`.
- The launcher panel is borderless (`.borderless` + `.nonactivatingPanel`) so the target app stays frontmost; the target window is captured when the panel opens. Panel height is dynamic (grows/shrinks with results via a Combine subscription on `viewModel.objectWillChange`). Background is `.regularMaterial` with configurable opacity (`launcherOpacityKey`, default 0.85).
- **Launcher hotkey** (`GeneralSettingsView` / `HotkeyManager.openLauncher`): `KeyboardShortcuts.Name("openLauncher")`. The launcher shows results only when the query is non-empty (Spotlight behavior). Cmd+, opens Settings from the launcher.
- **Next Window hotkey** (`WindowSettingsView` / `HotkeyManager.nextWindow`): `WindowCycler` uses Accessibility to get the front app's windows, find the current main window, and raise the next one, so it works regardless of whether the system "Move focus to next window" shortcut is enabled or what keyboard layout is in use.
- **Next Display action** (`WindowAction.nextDisplay`, id `"nextDisplay"`): unlike other actions that flow through `LayoutEngine.frame(for:)` on a single screen, this one is intercepted in `CommandApplier.apply` (checked by `command.id == WindowAction.nextDisplay.commandID`) and handled by `moveToNextDisplay`, which finds the current screen via `WindowManipulator.screen(containing:)`, cycles to the next in `NSScreen.screens`, and uses `LayoutEngine.frameForNextDisplay` to preserve the window's relative position and size. The pure math is testable in `LayoutEngineTests`.
- **Export / Import** (`ConfigPorter`, app target): combines `CommandStore.commands` and `AppShortcutStore.shortcuts` into a single versioned JSON. Import calls `replace(with:)` on both stores, which clears old hotkey bindings and re-registers. Hotkey assignments themselves are not included (stored by KeyboardShortcuts in UserDefaults, keyed by `KeyboardShortcuts.Name`).
- App icon: drop a 1024x1024 PNG at `Resources/AppIconSource.png`, run `Scripts/make_icons.sh` (sips + iconutil generate `Resources/AppIcon.icns`), then rebuild — `package_app.sh` embeds it and sets `CFBundleIconFile`.
- Menu bar icon: drop a small monochrome (template-style) PNG at `Resources/MenuBarIcon.png`; `package_app.sh` bundles it and `StatusBarIcon` loads it at runtime (rendered as a template image, 18pt tall, falling back to the `rectangle.split.3x3` SF Symbol when absent).
- **Signing**: `package_app.sh` resolves the identity in order: `CODESIGN_IDENTITY` env → `Scripts/codesign-identity` file (git-ignored, first line) → ad-hoc. Ad-hoc signatures change on every rebuild and invalidate the Accessibility (TCC) grant — with a stable identity (self-signed "Trast" cert) the grant survives rebuilds. Fix per rebuild otherwise: `tccutil reset Accessibility com.trast.app`, re-toggle, relaunch.
- Opening System Settings panes uses `/usr/bin/open` via `Process` (`Accessibility.openSystemSettings()`), trying `x-apple.systemsettings:` then the legacy `x-apple.systempreferences:` scheme (this macOS build only registers the legacy one), then falls back to launching System Settings by bundle ID. `NSWorkspace.shared.open` fails to resolve these schemes when the app is launched from a terminal session.
- **App launching** (`LauncherController.installedAppItems`): the launcher shows all installed apps (from `AppScanner.cachedApps()`) in an "Applications" section, deduped against apps already in `AppShortcutStore` (by bundle ID or path). `AppScanner.refresh()` warms the cache on launch in a background queue. `LauncherItem.installedApp` carries an `NSImage` icon via `iconImage`; `LauncherRowView` renders `Image(nsImage:)` when available, falling back to SF Symbols.
- **Clipboard history** (`Clipboard/`): `ClipboardMonitor` polls `NSPasteboard.general.changeCount` every 0.5s via `DispatchSourceTimer`; on change reads `.fileURL` / `.tiff` / `.png` / `.string` types (in that order) and stores in `ClipboardStore` (versioned JSON at `~/Library/Application Support/Trast/clipboard.json`, max 100 items, pinned items never expire, configurable auto-clear). The launcher's Clipboard tab is the only clipboard UI — the `openClipboard` hotkey (registered in `HotkeyManager.registerAll`) calls `LauncherController.showClipboard()` (toggle: opens the launcher on the Clipboard tab). Search inside the tab matches full item content via `LauncherItem.searchText`; the standalone `ClipboardController` overlay was removed. Paste-on-select (in `LauncherController.pasteClipboardItem`) writes to `NSPasteboard.general` then posts `CGEvent` Cmd+V (virtualKey 9, `.maskCommand` flag). Settings in the Clipboard settings tab.
- **Snippet expansion** (`Snippets/`): `Snippet` model in Core (id, name, keyword, content, enabled; custom Codable with `decodeIfPresent` defaults). `SnippetStore` is versioned JSON at `~/Library/Application Support/Trast/snippets.json`. `SnippetExpander` creates a listen-only `CGEvent.tapCreate` on `.keyDown`; requires **Input Monitoring** permission (`CGPreflightListenEventAccess` / `CGRequestListenEventAccess`, prompted on first enable — a new permission distinct from Accessibility). Maintains a keystroke buffer; on each keyDown, appends the Unicode char (via `keyboardGetUnicodeString`) and checks for exact buffer == keyword match. The buffer resets on space/return/escape/tab, on any keyDown with Cmd/Option/Control held (pastest/select-all leaked their letter into the buffer), on any key that produces no text (arrows, F-keys, Home/End — cursor moved), on mouse clicks (global `NSEvent` monitor) and on frontmost-app changes (`NSWorkspace.didActivateApplicationNotification`); without these resets, residue from earlier typing makes `buffer == keyword` fail ("works on second try" symptom). On match: schedules injection on a background serial queue after a ~30ms settle delay (lets the final physical keystroke finish so synthetic events never race real ones), sends `keyword.count` backspace CGEvents, then (after a short phase gap) injects expansion text char-by-char via `keyboardSetUnicodeString` with ~12ms pacing between keystrokes and a ~6ms keyDown-to-keyUp gap (fast sub-frame posts get coalesced by apps and drop characters — seen as keyword residue and mangled expansions). Keystrokes landing in Trast's own key window (launcher search, settings fields) are ignored so editing a keyword in Settings never fires the snippet. All injected events use a **private `CGEventSource`** (`CGEventSourceStateID(rawValue: -1)` — the `.private` case is not exposed in this SDK's Swift overlay) so physical keys held during expansion can't suppress them, and carry a magic tag in `eventSourceUserData` so the tap callback ignores its own output (without this, expansion text feeds back into the keystroke buffer and breaks the next match). Master toggle in General settings (`snippetsEnabledKey`, default false). Snippets CRUD in the Snippets settings tab.
- **Hyper key** (`Hyperkey/`): Caps Lock → ⌃⌥⇧⌘ (`HyperkeyEngine`; master toggle `hyperKeyEnabledKey`, default false; `hyperSymbolKey` shows ⌃⌥⇧⌘ as ✦). Caps Lock is not usable at the CGEvent level — each press emits one `flagsChanged` per lock TOGGLE and releases emit nothing — so press/release is detected with a passive `IOHIDManager` (keyboard devices, usage page 0x07 / usage 0x39; needs Input Monitoring, prompts via `CGRequestListenEventAccess` when `IOHIDManagerOpen` returns `kIOReturnNotPermitted`). An active session `CGEventTap` (flagsChanged + keyDown + keyUp) consumes the caps `flagsChanged` (lock never engages, lone tap does nothing) and, while caps is held, inserts the four modifiers into every event's flags — Carbon hotkey matching and recorders read event flags, so KeyboardShortcuts' `onKeyUp` dispatch and the recorder work unchanged. **The keyboard lock/LED logic lives below the CGEvent layer** (consuming the flagsChanged does not stop the LED), so the engine also remaps Caps Lock → F18 at the HID driver level via `/usr/bin/hidutil property --set UserKeyMapping` (`0x700000039`→`0x70000006D` — page<<32|usage, 9 hex digits; a wrong Src silently no-ops and caps keeps toggling the lock) on start and reverts (empty mapping) on stop — the tap consumes the resulting F18 keyDown/keyUp so apps never see a stray key. hidutil needs no root; mappings reset on reboot, so a crash can leave caps as F18 until the next toggle/reboot, and the remap REPLACES any personal Caps Lock remap set in System Settings (restores to factory, not previous). If the HID monitor can't open (no Input Monitoring) the engine tears the whole tap down so Caps Lock keeps working normally. Known limitation: external keyboards on macOS 26+ don't pass CGEventTaps, so the mutation can't reach their keyDowns — hyper detection still works but hotkeys only fire from the built-in keyboard (fix would need IOKit HID seizure like feedthejim/hyperkey). Synthetic per-modifier `flagsChanged` events (private `CGEventSource`, `eventSourceUserData` tag) keep session modifier state consistent for other apps. Requires Accessibility + Input Monitoring (warnings in the Hyper Key section of General settings). Must quit Hyperkey.app first (two active remappers conflict); its driver-level caps→⌘ HID remap survives until reboot or `hidutil property --set '{"UserKeyMapping":[]}'` (during that window caps produces ⌘ flagsChanged, which the tap passes through with hyper inserted — still works since ⌘ is part of the combo). ✦ display: `HotkeyDisplay` (Core, pure, tested) collapses the `⌃⌥⇧⌘` prefix when carbonModifiers == the four Carbon bits; labels use `Shortcut.hyperDescription` (`Hotkeys/HotkeyLabel.swift`) in `CommandListView`, `AppShortcutListView`, `LauncherView`. `HotkeyRecorderView` (Settings) replaces `KeyboardShortcuts.Recorder` at all sites — same `setShortcut`/`getShortcut` storage, but ✦ rendering (the package's `RecorderCocoa` hardcodes `"\(shortcut)"` and its `Bundle.module` strings can't ship in the packaged app) and `performKeyEquivalent` interception so menu equivalents (⌘W etc.) record instead of firing. Mirrors RecorderCocoa rules (bare Tab bubbles, Esc cancels, Backspace/Delete clears, shift-only beeps); CANNOT pause hotkey dispatch or warn on system-taken combos (`isPaused`/`isTakenBySystem`/`shortcutByNameDidChange` are internal to the package). The menu bar still uses SwiftUI `.keyboardShortcut` (system-rendered glyphs — no ✦ there).
- **Edge gap presets**: the gap setting uses a segmented picker (Small=10px, Medium=20px, Large=40px, Extra Large=60px) instead of a raw px input. The gap is applied via `LayoutEngine.usableArea(in:gap:)` which insets the `visibleFrame`. `LayoutEngine.Request` also has an `interGap` parameter (defaults to 0) for inter-window gaps, but it is not currently passed by `CommandApplier` (revisit later).
